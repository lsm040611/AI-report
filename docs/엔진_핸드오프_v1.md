# 엔진 → UI 핸드오프 v1

`UI-엔진_통합명세_v1.md` §0 체크리스트의 **4·5·6번**과 §5 확인 사항 7개에 대한 답입니다.

산출물은 전부 `docs/engine_handoff/` 아래에 있고, **손으로 쓴 예시가 아니라
엔진을 실제로 돌려서 나온 것**입니다. `py -3.10 tools/make_handoff.py` 로 언제든
다시 만들 수 있습니다.

---

## 0. 체크리스트 현황 갱신

| # | 산출물 | 소유 | 이전 | 지금 |
|---|---|---|---|---|
| 4 | 엔진 실제 출력 샘플 (카드 JSON 3종) | 엔진 | ⬜ | ✅ `engine_handoff/cards/` |
| 5 | 엔진 API 시그니처 | 엔진 | ⬜ | ✅ `engine_handoff/api.json` + 아래 §2 |
| 6 | 리포트 본문 렌더 산출물 | 리포트 형식 | ⬜ 미착수 | ✅ **이미 있습니다** — 아래 §3 |

**6번이 이 문서의 핵심입니다.** 통합 명세는 리포트 본문을 "미착수 · 별도 트랙"으로
적어 두었는데, 실제로는 엔진 쪽에 §1~§4 본문 렌더러가 이미 완성돼 있습니다.
`data-section` · `data-sentence-id` · 의미 기반 emphasis 클래스까지 통합 명세가
요구한 형태 그대로 나옵니다. placeholder 를 채울 수 있습니다.

## 1. 통합 지점 5개 — 엔드포인트 대응표

| | 지점 | 엔드포인트 |
|---|---|---|
| ① | 파일 업로드 → 판정 | `POST /uploads/analyze` |
| ② | 검증 확정 → 카드 생성 | `POST /uploads/{draftId}/commit` |
| ③ | 카드 → 리포트 본문 렌더 | `GET /reports/{id}/body` · `GET /reports/{id}/evidence` |
| ④ | 리포트 → PDF | `GET /reports/{id}/pdf` · `POST /reports/pdf/prepare` |
| ⑤ | 카드 집계 → 인사이트 | `GET /insights/courses` · `GET /insights/course/{courseId}` |

이 밖에 **`GET /contract`** 를 하나 더 만들었습니다. §5 에서 물어보신 고정 집합
(issueCode · severity · 섹션 id · emphasis 클래스)을 **한 번의 호출로** 전부
받아 갈 수 있습니다. UI 에 상수를 복사해 두지 마시고 이걸 부르시면, 엔진이 어휘를
늘렸을 때 화면이 조용히 어긋나는 일이 없습니다.

## 2. 지점별 실제 응답

### ① `POST /uploads/analyze`

`multipart/form-data` 로 `file` 하나. 과정 카드에서 진입했으면
`?entryCourseKey=crs-xxxx` 를 붙입니다 (프리필 경로).

**카드를 만들지 않습니다.** 담당자가 검증 화면에서 확인·수정을 마치고 ②를 부를
때 비로소 카드가 생깁니다. 여기서 취소하면 남는 것은 저장된 파일 하나뿐입니다.

```jsonc
{
  "draftId": 1,                                  // ② 에 넘길 값
  "filename": "20260519_1차수_A조.xlsx",
  "sourceType": {
    "type": "누적교육",
    "evidence": "판정 근거 — 차수 표기(1차수) 존재 → 회차 간 성장 연결 대상",
    "confirmedByOperator": false
  },
  "courseMatch": {
    "mode": "create",
    "suggestedCourseId": null,
    "suggestedTitle": "Global Negotiation Program (GN-1)",
    "evidence": "제안 근거 — 차수 표기(1차수)는 있으나 이름이 충분히 닮은 기존 과정이 없습니다.",
    "candidates": [{ "courseId": "...", "title": "...", "score": 0.91 }]
  },
  "wave": { "suggested": 2, "basis": "2026-07 시행 · 직전 1회" },   // 진단서베이일 때만
  "context": { "과정명": "...", "차수": "1차수", "강사": "...", "날짜": "2026-05-19" },
  "rows": [
    {
      "rowNumber": 12,                 // 엑셀 행 번호 (1부터)
      "sheet": "1차수_A조",
      "issueCode": "EMPID_FORMAT",
      "severity": "error",
      "field": "empId",
      "message": "사번 형식 오류 — 숫자 0이 문자 O로 입력됨",
      "originalValue": "EMP-1O47",
      "suggestedValue": "EMP-1047",
      "name": "박민지",
      "empId": "EMP-1O47",
      "candidates": [ /* DUPLICATE_NAME 일 때만 */ ]
    }
  ],
  "summary": { "recognized": 30, "ok": 27, "errors": 2, "warnings": 1 },
  "sheets": ["1차수_A조"],
  "warnings": []
}
```

명세와 다른 점은 **필드 이름 두 개**뿐입니다.

- `rows[].rowNumber` 에 `sheet` 를 함께 실었습니다. 한 파일에 시트가 여럿이면
  행 번호만으로는 어느 시트인지 알 수 없어서입니다.
- `rows[]` 에 `name`·`empId` 를 넣어 두었습니다. UI 표에 바로 쓰시라고요.

`GET /uploads/drafts/{draftId}` 로 판정 결과를 다시 꺼낼 수 있습니다
(새로고침·뒤로가기 대비).

### ② `POST /uploads/{draftId}/commit`

```jsonc
{
  "confirmedSourceType": "누적교육",
  "confirmedCourse": { "mode": "link", "courseId": "crs-13032c" },
  //  또는           { "mode": "create", "newTitle": "협상 스킬 심화 2기" }
  "confirmedWave": 2,                            // 진단서베이일 때만
  "rowFixes": [
    { "rowNumber": 12, "field": "empId", "value": "EMP-1047" },
    { "rowNumber": 21, "field": "score", "value": "92", "label": "갈등 조정" }
  ],
  "excludedRows": [21],
  "operator": "김담당",
  "generate": true                               // 문장 생성·리포트까지 이어서
}
```

응답:

```jsonc
{
  "draftId": 1, "uploadId": 1,
  "courseId": "crs-13032c", "courseTitle": "협상 스킬 심화", "courseCreated": true,
  "cards":  [{ "cardId": 1, "name": "강지우", "empId": null, "status": "regular",
               "maxSeverity": "review", "sendable": true, "blockedBy": null }],
  "flags":  [{ "cardId": 3, "empId": null, "name": "홍민아",
               "severity": "hold", "code": "non_regular_participant",
               "message": "발송 전 담당자 확인 필수" }],
  "generation": { "processed": 12, "accepted": 12, "rejected": 0, "rejects": [] },
  "reports": [{ "card_id": 1, "name": "강지우", "report_id": 1,
                "html": "/reports/1/html" }],
  "warnings": []
}
```

세 가지를 약속드립니다.

1. **확정값은 재판정하지 않습니다.** 엔진이 `누적교육`으로 봤어도 담당자가
   `단발특강`으로 확정했으면 그대로 갑니다. 카드에는
   `"evidence": "담당자가 검증 화면에서 확정한 유형입니다 (엔진 재판정 없음)"` 로
   남습니다.
2. **`rowFixes` 는 원본 엑셀을 고치지 않습니다.** 카드 생성 입력에만 반영되고,
   무엇을 무엇으로 바꿨는지 `provenance.operator_fixes` 에 남습니다.
3. **같은 draftId 로 두 번 커밋하면 409** 입니다. 중복 생성 방지.

`courseId` 발급 주체는 **엔진**입니다 (§5-5 의 답). 같은 과정명이면 언제 불러도
같은 값이 나옵니다 — 영문이 섞여 있으면 그걸 쓰고(`executive-presentation-skills`),
순한글이면 짧은 해시를 붙입니다(`crs-13032c`).

담당자가 확정한 표기는 **표기 변형 사전**에 저장되어, 다음 업로드부터
`courseMatch.mode` 가 `link` 로 자동 매칭됩니다.

### ③ `GET /reports/{id}/body`

```jsonc
{
  "reportId": 1, "cardId": 1,
  "maxWidth": 760,
  "toc": [ { "id": "items", "label": "항목별 평가" },
           { "id": "feedback", "label": "서술 피드백" },
           { "id": "next", "label": "다음 학습 제안" } ],
  "html": "<div data-section=\"items\"> … </div>…",
  "css": "…",
  "footerHtml": "<footer>…</footer>",
  "sentenceCount": 2
}
```

- `toc` 는 **실제로 렌더된 묶음만** 담습니다. 이전 회차가 없으면 `compare` 가
  목차에도 본문에도 없습니다 (빈 섹션 금지).
- `html` 에는 `<html>` 껍데기가 없습니다. 그대로 placeholder 안에 넣으시면 됩니다.
- 사이드바가 이미 보여 주는 이름·과정 머리글은 빠져 있습니다.

`GET /reports/{id}/evidence` (또는 `?sentence_id=s1`):

```jsonc
{ "sentenceId": "s1",
  "ruleId": "R-17",
  "aiText": "가격 조정을 언급하는 대목에서 표현을 다듬어 볼 만합니다.",
  "sourceRef": "20260519_1차수_A조.xlsx › 1차수_A조 › 7행",
  "sourceText": "\"We will raise the price\" → \"We may need to adjust our pricing\"" }
```

### ④ PDF

- `GET /reports/{id}/pdf` — 파일 하나
- `POST /reports/pdf/prepare?upload_id=1` — 발송 승인 시 일괄 사전 생성,
  `{ empId, name, pdfUrl, filename, generatedAt, blockedBy }` 배열

파일명은 `{확정 과정명}_{차수}_{구성원명}_{발송일YYYYMMDD}.pdf` 입니다.
파일에 적혀 있던 원본 표기가 아니라 **담당자가 확정한 과정명**을 씁니다.

⚠️ **PDF 는 지금 브라우저 인쇄 경로입니다.** 파이썬만으로 한글 PDF 를 제대로
뽑으려면 WeasyPrint 가 필요하고, 그건 윈도우에서 GTK 를 따로 깔아야 합니다.
팀원 전원이 비개발자라 필수 의존성으로 두지 않았습니다. 지금은 `/pdf` 가
`X-Pdf-Fallback: weasyprint-not-installed` 헤더와 함께 인쇄용 HTML 을 돌려줍니다.
`pip install weasyprint` 만 되면 코드 변경 없이 진짜 PDF 로 바뀝니다.
**서버를 어디에 올릴지 정해지면 그때 결정하시죠.**

### ⑤ 인사이트

`GET /insights/courses` → 2단 셀렉터용 목록.
`GET /insights/course/{courseId}` → 유형별로 모양이 다릅니다.

```
누적교육   trend[] · areas[] · areasNotCompared[] · insights[]
단발특강   average · distribution[] · areas[] · trend:null · insights[]
진단서베이  waves[] · byRelation[] · insights[]
```

- **과정 횡단 통합 지표는 없습니다.** 그런 엔드포인트를 만들지 않았습니다.
- **회차 간 평가 영역 구성이 다르면 그 항목은 비교하지 않고**
  `areasNotCompared` 로 따로 빼서 알려 드립니다.
- 자동 인사이트 문구는 지어내지 않습니다. 점수에서 곧바로 읽히는 사실만 옮기고,
  어느 숫자에서 나왔는지 `basis` 에 함께 싣습니다.

```jsonc
{ "text": "1차수부터 2차수까지 과정 평균이 0.32점 올랐습니다.",
  "basis": "1차수 3.78 → 2차수 4.1" }
```

## 3. 리포트 본문 렌더 — 이미 있습니다 (체크리스트 6번)

`docs/engine_handoff/report_body/*.html` 를 브라우저로 열어 보시면 바로 보입니다.
왼쪽 사이드바는 미리보기용 흉내이고, **엔진이 주는 것은 오른쪽 본문과 CSS 뿐**입니다.

통합 명세 §2-③ 이 요구한 것을 하나씩 대조하면:

| 요구 | 상태 |
|---|---|
| 본문 최대 폭 760px | ✅ `body.maxWidth` |
| 섹션 순서·ID 고정 (items → feedback → compare → next) | ✅ |
| 각 섹션 최상위에 `data-section` | ✅ 묶음마다 `<div data-section="…">` |
| §3 은 이전 회차 없으면 **생성하지 않음** | ✅ 목차에서도 빠집니다 |
| §2 문장마다 `data-sentence-id` | ✅ AI 생성 문장에만 붙습니다 |
| emphasis 3종을 **의미 기반 클래스명**으로 | ✅ `em-issue-expression` / `em-corrected-expression` / `em-key-concept` |
| 엔진이 인라인 색상을 넣지 않을 것 | ✅ 본문에 인라인 색상 0건 |
| `language:"en"` 은 원문 + 번역 병기 (R-13) | ✅ 번역이 본문, 영어 원문은 아래 노트 |
| 진단서베이 관계별 분리 + 요약본 원칙 | ✅ R-10 이 n<3 관계를 전체 평균에만 반영 |

**색은 `report.css` 세 줄만 갈아끼우시면 됩니다.** 본문 HTML 은 손대지 않아도
공통 디자인 시스템 토큰으로 넘어갑니다.

```css
em.em-issue-expression     { … }   /* 고칠 표현 */
em.em-corrected-expression { … }   /* 권장 표현 */
em.em-key-concept          { … }   /* 핵심 개념 */
```

한 가지 알려 드릴 변경이 있습니다. 지금까지 엔진 리포트는
**한눈에 → 성장 비교 → 역량별 → 서술 → 실천** 순서였는데, 통합 명세의
`items → feedback → compare → next` 에 맞추느라 **성장 비교를 서술 피드백 뒤로**
옮겼습니다. 순서를 되돌리려면 명세를 고쳐야 하니, 이대로 가도 괜찮은지만
확인 부탁드립니다.

## 4. §5 확인 사항 7개에 대한 답

**1. `issueCode` 고정 집합** — 11개입니다. `GET /contract` 의 `issueCodes` 가
전부이고, 여기 없는 코드는 엔진이 내보내지 않습니다. 각 코드에 `field`(UI 가
입력 필드를 고르는 키), `input`(`text|number|choice`), `default_severity` 가
달려 있습니다.

```
EMPID_FORMAT   EMPID_MISSING   SCORE_OUT_OF_RANGE   SCORE_NOT_NUMERIC
SCORE_MISSING  AVERAGE_MISMATCH  DUPLICATE_NAME     NAME_MISSING
EMAIL_FORMAT   EMAIL_MISSING   SCALE_UNKNOWN
```

새 검사를 넣을 때는 `contract.py` 를 먼저 고치게 해 두었습니다 —
목록에 없는 코드로 검증 결과를 만들려 하면 그 자리에서 터집니다.

**2. `rows` 검증과 `courseMatch.candidates` 계산 주체** — 둘 다 **엔진**입니다.
UI 서버 계산은 없습니다.

**3. `flags[].severity` 4개 고정** — 네, `notice` / `review` / `hold` /
`block_direct_quote` 넷뿐입니다. 엔진 내부 상수와 계약이 같은 값을 씁니다.

**4. 담당자 수정 유형을 재판정하지 않는가** — 하지 않습니다. 위 ② 참고.

**5. `mode: create` 시 courseId 발급 주체** — **엔진**입니다. 위 ② 참고.

**6. 진단서베이 `wave` 가 카드 스키마에 있는가** — 없었습니다. 그래서
`card.context._wave` 에 넣었습니다. 밑줄로 시작하는 키는 "원본 엑셀에서 온 값이
아니라 운영 단계에서 붙인 값"이라는 표시입니다. 같은 자리에
`card.context._course_id` 도 들어갑니다.

**7. 리포트 본문 렌더 산출물의 형태** — **HTML 문자열 + CSS 문자열**입니다.
컴포넌트가 아닙니다. 이유는 웹 화면과 PDF 가 같은 문서여야 하기 때문입니다
(§2-④ "웹 HTML 뷰와 동일한 내용·서식"). React 컴포넌트로 주면 PDF 경로에서
다시 렌더해야 하고, 그 순간 두 문서가 갈라집니다.

## 5. 아직 안 된 것 (숨기지 않고 적습니다)

| 항목 | 상태 | 비고 |
|---|---|---|
| PDF 실제 생성 | 브라우저 인쇄 경로 | WeasyPrint 설치하면 코드 변경 없이 전환 |
| 운영 데이터 (승인·발송·열람·요청) | 없음 | UI 소관이라 만들지 않았습니다. 영속화가 필요하면 말씀 주세요 |
| 월간 종합 리포트 콘텐츠 구조 | 미정 | 어떤 내용이 들어가야 하는지 먼저 정해 주셔야 합니다 |
| 사번·이메일 명부 | 별도 입력 | 제공된 샘플 데이터에 사번·이메일이 없어 `roster` 테이블로 따로 받습니다 |
| R-18 표준 역량 매핑 승인 | 대기 | 인사이트 역량 비교 정확도의 선행 조건 |

## 6. 통합 순서 제안
