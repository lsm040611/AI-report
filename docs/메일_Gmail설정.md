# 웹사이트에서 메일 보내기 (Gmail HTTPS)

Render 는 메일 포트(SMTP)를 막습니다. 587·465·2525 전부 확인했고 다 막혀
있습니다. 그래서 **HTTPS 로 보내는 길**을 씁니다 — 웹사이트를 여는 것과 같은
통로라 막히지 않습니다.

외부 메일 업체에 가입하지 않습니다. **지금 쓰는 지메일 계정 그대로**입니다.
전부 무료입니다.

**걸리는 시간 25~35분.** 한 번만 하면 됩니다.

---

## 큰 그림

```
1. 구글 클라우드에서 '이 프로그램이 내 지메일로 보내도 된다'는 열쇠를 만든다  (20분, 클릭 작업)
2. 메일설정.bat 을 더블클릭해서 그 열쇠로 권한을 받는다                    (2분)
3. 나온 값 세 개를 Render 에 넣는다                                     (3분)
```

---

## 1단계 — 구글 클라우드 프로젝트 만들기

1. <https://console.cloud.google.com> 접속 (지메일 계정으로 로그인)
2. 화면 맨 위 왼쪽, 로고 옆의 **프로젝트 선택** 을 누릅니다
3. 오른쪽 위 **새 프로젝트**
4. 이름은 아무거나 — `hr-report` 정도로 하고 **만들기**
5. 만들어지면 다시 맨 위에서 그 프로젝트를 **선택**합니다

> 조직·위치를 물으면 그냥 두셔도 됩니다.

## 2단계 — Gmail API 켜기

1. 왼쪽 위 **☰ 메뉴** → **API 및 서비스** → **라이브러리**
2. 검색창에 `Gmail API` 입력 → 나오는 항목 클릭
3. **사용** 버튼

## 3단계 — 동의 화면 만들기

"이 프로그램이 권한을 요청합니다" 하고 뜨는 화면을 미리 만드는 단계입니다.

1. **API 및 서비스** → **OAuth 동의 화면**
2. User Type 은 **외부** → **만들기**
3. 채울 것 세 개만:
   - 앱 이름: `HR 리포트 엔진`
   - 사용자 지원 이메일: 본인 지메일
   - 개발자 연락처 정보: 본인 지메일
4. **저장 후 계속** → 범위 화면도 **저장 후 계속** (여기선 아무것도 안 합니다)
5. **테스트 사용자** 화면에서 **+ ADD USERS** → **본인 지메일 주소 입력** → 저장

   ⚠️ **이걸 빠뜨리면 나중에 "액세스 차단됨" 이 뜹니다.**

6. **저장 후 계속** → **대시보드로 돌아가기**

## 4단계 — ⚠️ 게시하기 (빠뜨리면 7일 뒤 고장납니다)

3단계에서 만든 동의 화면은 지금 **"테스트"** 상태입니다. 이 상태로 두면
**받은 권한이 7일 뒤 만료되어 발송이 갑자기 멈춥니다.**

1. **OAuth 동의 화면** 화면에 있는 **앱 게시** 버튼을 누릅니다
2. "확인 필요" 같은 안내가 뜨면 **확인** 을 눌러 진행합니다

> 게시해도 심사를 받는 건 아닙니다. 본인만 쓰는 앱이라 그대로 쓰시면 됩니다.
> 나중에 로그인할 때 "Google에서 확인하지 않은 앱" 경고가 뜨는데,
> **고급 → 이동** 을 누르면 됩니다. 본인이 만든 앱이니 정상입니다.

## 5단계 — 열쇠 만들기

1. **API 및 서비스** → **사용자 인증 정보**
2. 위쪽 **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**
3. 애플리케이션 유형: **데스크톱 앱** ← 꼭 이걸로
4. 이름은 아무거나 → **만들기**
5. 창이 뜨면서 값 두 개가 나옵니다. **이 창을 닫지 마세요.**
   - **클라이언트 ID** (`...apps.googleusercontent.com`)
   - **클라이언트 보안 비밀** (`GOCSPX-...`)

## 6단계 — 권한 받기

1. `suni` 폴더의 **`메일설정.bat`** 을 더블클릭
2. 5단계의 값 두 개를 붙여넣습니다
3. 브라우저가 열립니다 → 계정 선택 → (경고 뜨면 **고급 → 이동**) → **허용**
4. 검은 창으로 돌아오면 **값 세 개**가 적혀 있습니다

## 7단계 — Render 에 넣기

Render → **hr-report-engine** → **Environment** → **+ Add Environment Variable**
로 세 개를 넣고 **Save Changes**.

| Key | Value |
|---|---|
| `HR_GMAIL_CLIENT_ID` | 6단계에 나온 값 |
| `HR_GMAIL_CLIENT_SECRET` | 6단계에 나온 값 |
| `HR_GMAIL_REFRESH_TOKEN` | 6단계에 나온 값 |

2~3분 뒤 재시작됩니다.

## 8단계 — 확인

```
https://hr-report-engine.onrender.com/mailcheck
```

```json
{"ok": true, "transport": "gmail-api", "reason": "구글에서 발송 권한을 확인했습니다"}
```

`ok: true` 면 끝입니다. 이제 **웹사이트에서 발송이 실제로 나갑니다.**

---

## 안 될 때

| 나오는 말 | 뜻과 고칠 곳 |
|---|---|
| `액세스 차단됨` / `access_denied` | 3단계 **테스트 사용자**에 본인이 없습니다 |
| `invalid_client` | 5단계 값을 잘못 복사했습니다 |
| `invalid_grant` | 권한이 만료됐습니다 → 4단계 **게시**를 했는지 확인하고, `메일설정.bat` 다시 실행 |
| `refresh token 이 오지 않았습니다` | 구글 계정 > 보안 > **타사 앱** 에서 이 앱 권한을 지우고 다시 |
| 브라우저가 안 열림 | 검은 창에 적힌 주소를 직접 복사해서 여십시오 |

## 알아 두실 것

- **보내는 주소는 권한을 준 지메일 계정**입니다. 받는 사람에게 그 주소로 갑니다
- 지메일 개인 계정은 **하루 500통** 한도입니다. 우리는 한 번에 4~9통이라 넉넉합니다
- 값 세 개는 `gmail.env` 에도 저장됩니다 (깃에 안 올라갑니다). 내 컴퓨터에서
  서버를 켜도 같은 방식으로 나갑니다
- 이 길이 열려 있으면 SMTP 설정(`HR_SMTP_USER`·`HR_SMTP_PASS`)은 없어도 됩니다.
  둘 다 있으면 **HTTPS 쪽을 씁니다**
