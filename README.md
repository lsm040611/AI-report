# HR 리포트 엔진 — 인수인계 문서

평가 엑셀을 받아 **개인별 리포트를 만들고 각자에게 1:1로 메일 발송**하는 시스템.
Google 스프레드시트 + Apps Script 로 동작하며 별도 서버가 없다.

---

## 1. 이게 무엇을 하나

```
평가 엑셀 드래그앤드롭
   ↓  파일을 읽되 저장하지 않음
확인 화면에서 과정·차수 검토·수정
   ↓  사람이 승인해야 저장
스프레드시트 DB 적재 (배치 단위 · 되돌리기 가능 · 원본 보관)
   ↓
대상자 이메일 등록 → 결과 조회·필터 → 이상치 확인
   ↓
개인별 리포트 생성 → 미리보기 → PDF
   ↓  워밍업을 끝내야 열림
1:1 개별 발송 → send_log 기록
```

**두 종류의 평가를 다룬다.**

| 유형 | 구조 | 예시 |
|---|---|---|
| 교육평가 | 1행 = 1대상자 | 협상 교육 차수별 강사 평가, 특강 평가지 |
| 서베이(360°) | 1행 = 1응답, 한 사람에 여러 응답 | 리더십 360° 진단 |

## 2. 처음 세팅하는 법

### 2-1. 스프레드시트와 스크립트

1. `sheets.new` 로 스프레드시트 생성 (이름 예: `HR리포트엔진`)
2. **확장 프로그램 → Apps Script**
3. `apps-script/` 의 파일을 **전부** 추가한다
   - `.gs` 는 ＋ → **스크립트**, 이름에서 `.gs` 를 뺀 이름으로
   - `71_dashboard.html` 은 ＋ → **HTML**, 이름 `71_dashboard`
   - `appsscript.json` 은 ⚙️ 프로젝트 설정에서 "매니페스트 파일 표시" 를 켜야 보인다
4. `Cmd+S` 저장

### 2-2. 시트 만들기

`60_store.gs` 열고 → 함수 드롭다운 `setupSheets` → ▶ 실행 → 권한 승인
`10_config.gs` 열고 → `setupConfigSheet` → ▶ 실행

스프레드시트를 **새로고침**하면 상단에 `HR 리포트` 메뉴가 생긴다.

### 2-3. 권한

`appsscript.json` 에 권한을 명시해 두었다. 자동 추론에 맡기면 좁게 잡혀 실패한다(트러블슈팅 참고).

| 권한 | 쓰는 곳 |
|---|---|
| `drive` | 원본 xlsx 보관, PDF 저장 |
| `spreadsheets` | DB |
| `script.container.ui` | 작업 화면(대화상자) |
| `userinfo.email` | 적재 이력에 담당자 기록 |
| `gmail.send` / `script.send_mail` | 리포트 발송 |

권한을 바꾼 뒤에는 **기존 승인을 지우고 다시 승인**해야 한다 →
[myaccount.google.com/permissions](https://myaccount.google.com/permissions)

## 3. 매번 하는 작업 (운영 절차)

**HR 리포트 → 작업 화면 열기**

### ① 엑셀 업로드
엑셀을 끌어다 놓고 **읽어서 확인하기**. 아직 저장되지 않는다.

확인 표에서 **과정(대분류)** 과 **차수**를 검토한다. 값을 고치면 고친 값으로 저장된다.
- 과정명은 기존 과정이 자동완성으로 뜬다 — 오타로 새 과정이 생기는 것을 막는다
- **과정명이나 차수가 비면 저장 버튼이 잠긴다.** 원본에 차수 표기가 없으면 직접 넣어야 한다
  (특강처럼 차수 개념이 없으면 `특강` 또는 날짜를 넣는다)
- 이미 올린 파일이면 `재적재` 배지가 뜨고 이전 값이 무엇이었는지 함께 보여준다

**이 내용으로 저장** → 배치 단위로 기록되고 원본 xlsx 가 드라이브에 보관된다.

### ② 대상자·이메일
표에서 이메일을 직접 입력하면 바로 저장된다. 엑셀에서 `이름 탭 이메일` 을 복사해 일괄 붙여넣기도 된다.
**이메일이 없으면 발송 대상에서 빠진다.**

### ③ 결과 조회·필터
성장률과 참여 매트릭스. 필터 4축은 6절 참고.

### ④ 이상치
원본 데이터의 문제를 모아 보여준다. **원본은 고치지 않는다** — 점수·평균은 재계산값을 쓴다.
원본 수정이 필요하면 담당 강사에게 확인 후 파일을 다시 올린다.

### ⑤ 리포트 생성
대상 묶음(과정 또는 진단)을 고르고 대상자를 체크한다.
- **미리보기** — 실제 리포트를 팝업으로 확인
- **선택분 PDF 생성** — 드라이브 `HR리포트엔진_리포트/<과정> <날짜>/` 에 저장
- **선택분 발송** — 워밍업을 끝내야 열린다(4절)

### 적재 이력
과거 배치를 되돌릴 수 있다. 되돌리면 그 배치의 회차 데이터만 지워지고
**대상자 명단과 입력해 둔 이메일은 남는다.**

## 4. 발송 (반드시 이 순서로)

발송은 되돌릴 수 없다. 4중 안전장치가 걸려 있다.

```
1. 워밍업 미완료 → 발송 버튼 잠김
2. Gmail 잔여 할당량 확인
3. config 일일발송상한 확인
4. 이메일 미등록자는 제외하고 사유를 로그에 남김
```

### 워밍업 절차 (최초 1회, 발신 계정을 바꿀 때마다)

1. 리포트 탭에서 대상자 **한 명만** 체크
2. 빨간 줄의 **워밍업 발송하기** → 받을 주소 입력 (본인 주소 권장)
3. **수신함에서 눈으로 확인한다**
   - 스팸함이 아니라 받은편지함에 왔는가
   - PDF 첨부가 열리는가
   - 한글이 깨지지 않는가
   - 발신자명이 의도한 대로 보이는가
4. `config` 시트에서 `워밍업완료` 를 **YES** 로 직접 입력
5. 화면에서 `확인했음 — 상태 다시 읽기` → 발송 버튼이 열린다

**코드가 자동으로 YES 를 찍지 않는 것은 의도적이다.** 사람이 수신함을 봐야 워밍업의 의미가 있다.

### 발송 방식
- 전부 **1:1 개별 발송**. 참조·숨은참조를 쓰지 않는다 —
  개인 평가 결과가 다른 수신자에게 보이면 그 자체로 사고다
- 연속 발송 사이 4초 간격 (스팸 판정 회피, `config` 에서 조정)
- 결과는 `send_log` 시트에 전부 기록된다

### 발송량 한도
| 계정 | Gmail 일일 한도 |
|---|---|
| Workspace (회사 계정) | 1,500~2,000통 |
| 개인 Gmail | 100통 |

`config` 의 `일일발송상한` 은 별도의 자체 제한이다. 워밍업 초기에는 낮게 두고 단계적으로 올린다.

## 5. 설정 (`config` 시트)

| 키 | 기본값 | 설명 |
|---|---|---|
| 발신자명 | 교육운영팀 | 수신자에게 보이는 이름 |
| 회신주소 | (비움) | 비우면 실행 계정 주소 |
| 일일발송상한 | 50 | 자체 제한. 직접 올린다 |
| 회차당발송간격초 | 4 | 연속 발송 사이 대기 |
| 최소응답수 | 3 | 360진단 익명성 기준 N |
| 워밍업완료 | NO | **YES 여야 발송이 열린다** |
| 워밍업발송수 | 0 | 자동 증가 |
| 메일제목 | `[{과정명}] {이름} 님 개인 피드백 리포트` | `{이름} {과정명} {차수} {날짜}` 치환 |

> `setupConfigSheet` 를 다시 실행하면 **기본값으로 초기화**된다. 주의.

## 6. 성장률 필터 — 무엇을 고르는가

| 축 | 값 | 의미 |
|---|---|---|
| 비교 기준 | `본인 참여 구간` (기본) | 본인 최초 ↔ 본인 최종. 중도 합류·이탈자도 자기 구간에서 산출 |
| | `코호트 전체 구간` | 1차수 ↔ 막차 양쪽 참여자만. 같은 잣대로 비교할 때 |
| | `직전 회차 대비` | 최근 두 회차 |
| 영역 기준 | `공통 영역만` (기본) | 비교 대상 회차 전부에 있는 영역만. **유일하게 정확** |
| | `전체 영역` | 회차마다 영역이 다르면 왜곡됨. 경고가 함께 뜬다 |
| 대상자 범위 | 전 회차 / 일부 / 단일 / 청강 포함 | |

**제외자는 절대 조용히 사라지지 않는다.** 항상 `대상 N명 / 제외 M명` 이 표시되고 제외 사유가 붙는다.

### 왜 '공통 영역만' 이 기본인가
1차수는 3영역, 2차수는 5영역으로 양식이 바뀌었다. 전체 평균끼리 비교하면 신규 영역 점수가 섞여
성장률이 거짓이 된다. 실제 샘플에서 류현수는 전체 평균 기준 `+0.2 상승` 이지만
공통 영역 기준으로는 `0.0 제자리` 이고, 사실은 Persuasion 이 `4.5 → 3.5` 로 떨어졌다.

### 본인 구간 기준을 쓸 때 따라붙는 것
사람마다 비교 구간이 다르므로 증감값을 나란히 비교할 수 없다. 그래서
- **회차당 증감**을 함께 산출한다
- 구간이 섞이면 안내 문구가 뜬다
- 비교에 쓰인 **영역 수**를 행마다 표시한다 (구간이 달라지면 영역 집합도 달라진다)

## 7. 360° 진단 익명성

**응답자가 적은 관계 구분은 개인이 특정된다.** 동료가 2명뿐인데 "동료 평가 2.5점 / 협업 회의가 어떻다"
를 그대로 실으면 둘 중 하나로 좁혀지고, 다음 진단부터 아무도 솔직하게 쓰지 않는다.

**게이트 규칙 (기본 N=3)**
1. 관계 구분별 응답 수를 센다
2. N 미만인 구분은 인접 구분과 **병합**한다 (`상사·동료` 형태)
3. 병합해도 N 미만이면 **점수·주관식 모두 비공개**
4. 전체 응답이 N 미만이면 그 사람 리포트를 아예 만들지 않는다

**게이트는 점수와 주관식 양쪽에 건다.** 주관식만 막고 관계군별 점수를 보여주면
상사 1명의 점수가 그대로 노출되어 의미가 없다.

**숨겼다는 사실은 숨기지 않는다.** 리포트에 이렇게 적힌다:
> [상사·동료] 응답 2건은 응답자 수가 적어 익명성 보호를 위해 표시하지 않았습니다.
> 해당 응답은 전체 평균에는 포함되어 있습니다.

전체 평균에 포함된다는 것을 명시해야 "구성원 평균과 전체 평균이 왜 다르냐" 는 문의가 없다.

## 9. 개발자에게

### 코드를 고치기 전에 읽을 것
**`BEHAVIORS.md` 를 먼저 읽으십시오.** 이상해 보이는 동작 대부분은 의도된 것이고,
그 이유가 거기 적혀 있다. 특히 5번(시간 축은 차수, 파일이 아님)과
14번(강조 표시 정규화)은 실제로 잘못 만들었다가 고친 것이다.

### 로컬에서 검증하는 법
```bash
cd hr-report-engine
./tools/run_all.sh          # 전체 검증
node tools/preview_reports.js && open preview/report_강지우.html
```

**로직은 순수 함수로 두고 Apps Script API 호출과 분리한다.**
`30_normalize.gs`, `41_cohort.gs` 는 Apps Script API 를 하나도 쓰지 않아 로컬 node 로 검증된다.
`20_xlsx.gs`(Utilities.unzip)와 `60_store.gs`(SpreadsheetApp)만 실환경이 필요하다.
새 로직을 추가할 때 이 경계를 지키면 검증 비용이 크게 줄어든다.

### 스키마를 바꿀 때
`SHEETS` 에 컬럼을 추가하면 `ensureColumns_` 가 기존 시트를 자동으로 넓힌다.
사용자가 시트를 지웠다 다시 만들 필요는 없다. 다만 **기존 행의 새 컬럼은 비어 있으므로**
그 데이터가 필요하면 엑셀을 다시 올려야 한다.

### 새 양식이 들어왔을 때
현재는 헤더 텍스트로 컬럼을 찾는다(위치가 아니라). 인식에 실패하면
`헤더인식실패` 이슈를 내고 대상자 0명으로 끝난다 — **조용히 틀린 값을 내지 않는다.**
수동 매핑 UI 는 아직 없다. 미구현 목록 참고.

| 증상 | 원인 / 조치 |
|---|---|

| 조회가 느림 | 첫 조회는 시트를 다 읽는다. 이후는 캐시(10분)를 쓴다. 적재·수정 시 캐시가 무효화된다 |
| 발송 버튼이 잠겨 있음 | `config` 의 `워밍업완료` 가 YES 인지 확인 |
| 리포트에 성장 섹션이 없음 | 그 사람의 참여 회차가 1개뿐이거나 공통 영역이 없음. 정상 동작 |
| 360진단이 "건너뜀" 으로 나옴 | `90_survey.gs` 를 안 넣었을 가능성 |
