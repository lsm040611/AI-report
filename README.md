# HR AI Report Engine

엑셀 평가지를 넣으면 **개인 피드백 리포트 HTML**이 나오는 백엔드입니다.
데이터 계약 v0.5의 구현체이고, **규칙 ID와 코드가 1:1로 대응**하도록 짜여 있어
계약서를 왼쪽에 두고 코드를 읽을 수 있습니다.

```
평가지.xlsx  →  스키마 인식  →  정제 규칙 19개  →  카드
             →  검수 관문  →  AI 생성(R-16 근거 검사)  →  리포트 HTML
                                                    └→  HRD 대시보드
```

교육 평가(누적·단발)와 360° 진단이 **같은 파이프라인**을 지나갑니다.
컬럼 위치·역량명·척도가 코드에 박혀 있지 않아, 처음 보는 양식도 그대로 통과합니다.

## 무엇을 만들었나 (요약)

**엔진만 있던 것을, 팀원이 링크 하나로 끝까지 쓰는 것으로 만들었습니다.**

| | |
|---|---|
| 담당자 | 링크 열기 → 사번 로그인 → 엑셀 올리기 → 검수 → 메일 발송 |
| 구성원 | 사번 로그인 → 자기 리포트 (회차별로) |
| 설치할 것 | 없음 (브라우저만) |

### 만든 것

- **화면 연결** — UI 프로토타입은 백엔드가 없어 호출 자리를 전부 `setTimeout`
  으로 흉내 내고 있었습니다. 그 자리를 실제 호출로 바꿨습니다.
  **마크업은 한 줄도 안 고쳤습니다** — 로직만 덧씌우는 방식이라(`web/patch.js`),
  UI 팀이 새 판을 주면 빌드 한 번으로 다시 붙습니다.
- **배포** — Render 무료. 비밀번호를 안 넣으면 바깥에서 아예 안 열립니다.
- **메일** — Render 가 SMTP 를 통째로 막아서(587·465·2525 전부 불통)
  **Gmail HTTPS API** 로 우회했습니다. 새 라이브러리 없이 표준 모듈만 씁니다.
- **사원 명부** — 평가지에는 이름뿐입니다. 사번·직급·이메일이 여기서 옵니다.
  없는 사람은 임시 사번으로 자동 등록하되 **메일 주소는 지어내지 않습니다.**
- **로그인** — 담당자는 인사팀 사번, 구성원은 본인 사번. 누구로 들어와 있는지
  화면 위에 계속 뜹니다.
- **여러 파일 동시 업로드** — 1차수·2차수를 함께 올리면 성장 비교가 그 자리에서
  완성됩니다. 파일별로 갈라 봅니다.
- **진행률과 남은 시간** — 생성·발송 둘 다. 1분 넘는 일에 아무것도 안 보이면
  고장으로 보입니다.

### 조용히 틀리던 것들 — 여기가 핵심입니다

보였으면 바로 알았을 텐데, **안 보여서 몰랐던 것들**입니다.

| 무엇 | 어떻게 보였나 |
|---|---|
| API 실패가 목(mock)으로 몰래 떨어짐 | 36건 중 9건이 정제 안 된 원문인데 화면상 구분이 없었습니다 |
| 동료 평가 원문이 그대로 실림 | 익명성 누수. 누가 썼는지 알 수 있었습니다 |
| 시험이 몰래 진짜 API 를 부름 | 목 모드라고 믿고 돌린 게 과금되고 있었습니다 |
| 발송 관문이 비어 있음 | 화면은 '보낼 수 없음' 이라 하고 **서버는 보내고** 있었습니다 |
| 100점 만점을 10점으로 잼 | 88점이 880% 가 되고 화면에서 100 으로 잘려 **전원 100점** |
| 패치가 실행 안 되는 자리에 들어감 | 파일도 만들어지고 페이지도 열렸습니다. 아무 일도 안 일어날 뿐 |

마지막 것 때문에 **빌드가 패치의 실행 위치를 검증하고, 아니면 중단**합니다
(`tools/build_web.py`).

## 0. 처음 받기 · 최신으로 맞추기

### 처음 받을 때 (한 번만)

폴더를 하나 만들고, 그 안에서 **마우스 우클릭 → `Git Bash Here`** 를 누른 뒤
아래를 붙여넣고 엔터.

```bash
git clone https://github.com/lsm040611/AI-report.git
```

> `Git Bash Here` 가 안 보이면 <https://git-scm.com/download/win> 에서 Git 을
> 먼저 설치하십시오. 설치는 계속 `다음` 만 누르면 됩니다.

GitHub 웹에서 **Download ZIP** 으로 받아도 실행은 되지만, **나중에 갱신이
안 됩니다.** 아래 `git pull` 을 쓰려면 반드시 `git clone` 으로 받으십시오.

### 최신 버전으로 맞출 때 (수정될 때마다)

받아 둔 폴더에서 **우클릭 → `Git Bash Here`** → 아래 한 줄.

```bash
git pull
```

전체를 다시 받는 게 아니라 **바뀐 줄만** 옵니다. 보통 몇 초면 끝납니다.

| 나오는 말 | 뜻 |
|---|---|
| `Already up to date.` | 이미 최신입니다. 할 것 없음 |
| `Fast-forward` 와 파일 목록 | 잘 받아졌습니다 |
| `Your local changes ... would be overwritten` | 본인이 파일을 고쳤습니다. 아래 참고 |

파일을 고쳐서 막혔다면, 고친 것을 잠시 치워 두고 받으면 됩니다.

```bash
git stash
git pull
```

그냥 폴더를 통째로 지우고 다시 `git clone` 해도 됩니다 — 필요한 건 전부
저장소에 있습니다.

### `git pull` 해도 안 오는 것들

일부러 뺀 것이라 **정상입니다.** 각자 만들면 됩니다.

| 안 오는 것 | 이유 |

## 1. 실행

Python 3.10 이상. Node·DB 서버·외부 워크플로 엔진은 필요 없습니다.

**Windows** — `start.bat` 더블클릭하면 서버가 뜨고 브라우저가 열립니다.
끄려면 창을 닫고, 뭔가 남은 것 같으면 `stop.bat`.

**직접 실행할 때**

```bash
pip install -r requirements.txt

python make_fixtures.py      # 테스트용 평가지 4종 생성
python smoke_test.py         # 전 구간 한 번 돌려보기 → out/*.html
python test_edge_cases.py    # 까다로운 양식 회귀 테스트

uvicorn main:app --port 8000
```

> Windows에서 `python` 이 PATH에 없으면 `py -3.10` 으로 바꿔 실행하세요.

| 주소 | 내용 |
|---|---|
| `http://127.0.0.1:8000/` | **업로드 화면.** 파일을 올리면 리포트 링크까지 나옵니다 |
| `/dashboard` | **HRD 대시보드** — 과정 단위 지표 |
| `/docs` | 프론트 팀과 공유할 API 계약서 (자동 생성) |
| `/contract` | UI 가 쓰는 고정 어휘 — issueCode·severity·섹션 id |
| `/rules` | 구현된 규칙 19개 — 계약 규칙표와 대조용 |
| `/health` | 현재 모드 확인 |

PDF가 필요하면 리포트를 브라우저로 열고 `Ctrl+P → 대상: PDF로 저장`.

## 2. 두 개의 모드

같은 코드가 두 가지 태도를 갖습니다. 환경변수로만 바뀝니다.

| 환경변수 | 기본 | 의미 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 없음 | 있으면 Claude API로 생성하고, 없으면 **목(mock) 생성기**로 돌아갑니다 |
| `HR_AUTO_APPROVE` | `1` | `1`이면 검수 관문을 자동 통과(데모), `0`이면 계약대로 담당자 승인 필요(운영) |
| `HR_MODEL` | `claude-opus-5` | 생성 모델 |
| `HR_EFFORT` | `medium` | 생성 깊이 (`low`~`max`) |
| `HR_DB_URL` | `sqlite:///./hr_report.db` | 저장소 |
| `HR_MAIL_ENABLED` | `0` | `1`이어야 메일이 실제로 나갑니다. 꺼져 있으면 **미리보기** |
| `HR_SMTP_HOST` / `HR_SMTP_PORT` | `smtp.naver.com` / `587` | 465면 SSL, 그 밖은 STARTTLS |
| `HR_SMTP_USER` / `HR_SMTP_PASS` | 없음 | 네이버는 **애플리케이션 비밀번호**를 씁니다 |

### API 키 넣기

**`api.env`** 를 열어 키만 채우면 됩니다. 이 파일은 `.gitignore` 에 있어
커밋되지 않습니다.

```ini
ANTHROPIC_API_KEY=sk-ant-...
HR_EFFORT=medium          # low | medium | high | xhigh | max
```

1. <https://console.anthropic.com> 에서 크레딧 충전(최소 $5)
2. 같은 화면에서 **월 지출 한도**를 걸어 두십시오 — 실수로 많이 나가는 것을 막습니다
3. `API keys → Create Key` 로 만든 값을 위에 붙여넣기

넣은 뒤 **한 번만** 실제로 호출해 확인하십시오. 평가지를 통째로 올리기 전에
문제를 잡을 수 있고, 한 건에 토큰이 얼마나 드는지도 보여 줍니다.

```powershell
py -3.10 check_api.py
```

환경변수를 직접 설정하면 그쪽이 이깁니다 — 잠깐 다른 키로 바꿔 볼 때 편합니다.

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
$env:HR_AUTO_APPROVE = "0"              # 운영 모드(담당자 승인 필수)
.\start.bat
```

**키가 없어도 전 구간이 돌아갑니다.** 목 모드는 원문을 재배열만 하므로 없는 사실을
만들지 않고, 그 문장이 섞인 리포트에는 푸터에 그 사실이 표기됩니다.

다만 **언어 모델이 있어야만 되는 것 두 가지**가 있습니다.

| 기능 | 목 모드 동작 |
|---|---|
| **영어 코멘트 한국어 번역** (R-13) | 번역하지 않고 영어 원문을 그대로 싣습니다 |
| **강조 의미 재판정** (R-05) | 서식 기반 판정을 그대로 씁니다 |

둘 다 배선은 끝나 있어 키를 넣는 순간 동작합니다. 화면에는 왜 건너뛰었는지가
`R-16 거부` 목록으로 표시됩니다.

### 리포트를 본인 메일로 보내기 (`mailer.py` · `gmail_api.py`)

주소는 평가지에 적혀 있으면 그것을, 없으면 **사원 명부**에서 가져옵니다.
열 이름은 아무래도 좋습니다 — `이메일`, `메일`, `연락처` 어느 것이든 **값의
모양**을 보고 주소를 찾아냅니다.

받는 사람은 **본인 주소로 고정**입니다. API 로도 받는 사람을 바꿔 지정할 수
없습니다. 실수 한 번으로 남의 피드백이 가는 일을 막기 위해서입니다.

보내는 길이 둘입니다.

| | 언제 쓰나 |
|---|---|
| **Gmail HTTPS API** (`gmail_api.py`) | 배포한 서버. Render 무료는 SMTP 를 통째로 막습니다(587·465·2525 전부 `Network is unreachable`) |
| **SMTP** (`mailer.py`) | 내 컴퓨터에서 돌릴 때 |

설정이 되어 있으면 HTTPS 쪽을 먼저 씁니다. 어느 길로 나가는지는
`/health` 와 `/mailcheck` 가 알려 줍니다 — **보내지 않고** 닿는지만 봅니다.
Gmail API 설정은 → **[docs/메일_Gmail설정.md](docs/메일_Gmail설정.md)**

#### 보내기 전에 세 겹으로 막습니다

메일은 되돌릴 수 없습니다.

1. **검수 관문** — `is_sendable()`. 청강생·동명이인 미해결·사번 불일치는 막습니다.
   전체 발송에서도 **건너뛴 사람과 이유가 표에 남습니다.**
2. **주소** — 없으면 목록에서부터 '보낼 수 없음' 으로 뜹니다.
3. **한 번 더 묻기** — 개별 발송은 받는 사람 주소를 보여 주고 확인을 받습니다.

**메일을 실제로 보내려면 각자 자기 계정을 등록해야 합니다.** 아래 4단계를
그대로 따라 하시면 됩니다. 10분이면 끝나고, **한 번만 하면 됩니다.**

> 왜 각자 해야 하나요?
> 메일을 보내려면 "누가 보내는 건데?"를 구글에 증명해야 합니다. 그래서 보내는
> 사람의 계정이 필요합니다. 남의 계정 정보는 저장소에 올리지 않습니다.
>
> **이 설정을 안 해도 프로그램은 다 돌아갑니다.** 리포트도 다 만들어집니다.

주소창에 붙여넣기: `https://myaccount.google.com/security`

`Google에 로그인하는 방법` → **2단계 인증** → `시작하기` →
휴대폰 번호 입력 → 문자로 온 6자리 숫자 입력 → `사용 설정`

#### 2단계 — 앱 비밀번호 받기

주소창에 붙여넣기: `https://myaccount.google.com/apppasswords`

이름 칸에 아무거나(`HR리포트`) 적고 **만들기** → **16자리**가 뜹니다.

```
abcd efgh ijkl mnop
```

이 화면은 **한 번만** 보입니다. 닫으면 다시 못 봅니다(다시 만들면 됩니다).

> **앱 비밀번호가 뭔가요?**
> 메일 프로그램 전용 열쇠입니다. 이걸로는 구글 계정에 **로그인할 수 없고**,
> 지메일 화면·드라이브도 못 엽니다. 메일을 보내는 것만 됩니다.
> 마음에 안 들면 위 주소에서 삭제하면 그 즉시 무효가 됩니다.

#### 3단계 — `mail.env` 파일 만들기

프로젝트 폴더(`start.bat` 이 있는 그 폴더)에 **메모장**으로 새 파일을 만들고
아래 다섯 줄을 붙여넣습니다.

```ini
HR_SMTP_HOST=smtp.gmail.com
HR_SMTP_PORT=587
HR_SMTP_USER=본인아이디@gmail.com
HR_SMTP_PASS=여기에16자리
HR_MAIL_ENABLED=1
```

- `HR_SMTP_USER` — 본인 지메일 주소를 **@gmail.com 까지** 그대로
- `HR_SMTP_PASS` — 2단계에서 받은 16자리 (띄어쓰기는 있어도 없어도 됩니다)

저장할 때 **파일 이름을 `mail.env`** 로, **파일 형식은 `모든 파일`** 로 바꾸십시오.
그냥 저장하면 `mail.env.txt` 가 되어 프로그램이 못 찾습니다.

#### 4단계 — 확인

`start.bat` 을 다시 실행하고 리포트를 만든 뒤 **본인 메일로 보내기** 를 누릅니다.

| 화면에 나오는 말 | 뜻 |
|---|---|
| `4/4명에게 보냈습니다` | 성공 |
| `미리보기 —` 로 시작 | 3단계가 안 됐습니다 (파일 이름이 `mail.env.txt` 인 경우가 대부분) |
| `SMTPAuthenticationError` | 앱 비밀번호가 아니라 로그인 비밀번호를 넣었습니다 |
| `평가지에 이메일이 없습니다` | 그 엑셀에 이메일 열이 없습니다. 정상입니다 |

#### 알아 두실 것

- `mail.env` 는 **깃에 올라가지 않습니다.** 커밋해도 빠지고, 팀원에게도 안 갑니다.
- 그러니 이 파일을 **카톡·메일로 남에게 보내지 마십시오.** 그때만 위험합니다.
- 발표 때 화면 공유하신다면 이 파일은 열지 마십시오.
- 어느 경우든 **버튼을 눌러야 나갑니다.** 업로드만으로는 아무에게도 안 갑니다.

네이버 계정을 쓰신다면 `HR_SMTP_HOST` 를 `smtp.naver.com` 으로, `HR_SMTP_USER` 를
**@naver.com 을 뺀 아이디만** 적고, 네이버 메일에서 `환경설정 → POP3/IMAP 설정 →
POP3/SMTP 사용` 을 켜시면 됩니다.

### 키 없이 실제 생성물 받기 — 이 폴더에서 Claude Code 에 `/ai`

API 키는 구독과 별도로 과금됩니다. 그래서 **생성 자리를 Claude Code 로 대신
채우는 길**을 열어 두었습니다. 원래 설계가 이걸 허용합니다 — 규칙은 '무엇을
써야 하는지'만 큐에 쌓고, 생성은 바깥에서 하기 때문입니다.

```
평가지 업로드  →  이 폴더에서 Claude Code 를 열고  /ai  →  브라우저 새로고침
```

`/ai` 하나가 내보내기 · 작성 · 반영을 다 합니다 (`.claude/commands/ai.md`).
특정 업로드만 다시 쓰려면 `/ai 12` 처럼 번호를 붙입니다.

내부적으로는 `ai_bridge.py` 가 큐를 `handoff_ai/요청.md` 로 꺼내고, 작성된
`handoff_ai/응답.json` 을 되돌려 넣습니다. 요청서에 담기는 지시문은 API 에
보낼 프롬프트와 **글자 그대로 같습니다.** 손으로 돌리려면:

```powershell
py -3.10 ai_bridge.py export     # 또는 ai_export.bat
py -3.10 ai_bridge.py import     # 또는 ai_import.bat
```

넘기는 재료는 R-11 이 이미 단서를 걷어낸 것이라 요청서에 응답자를 특정할
대목이 남지 않습니다. 돌아온 문장도 R-16 검수를 그대로 거칩니다.

## 3. 설계 전제

**규칙 코드에는 LLM 호출이 한 줄도 없습니다.** 생성이 필요한 작업은 `handoff` 큐에
쌓이고, `generation/worker.py` **한 파일만** 그 큐를 가져가 Claude API를 호출합니다.
돌아온 결과는 **R-16 검사를 통과해야만** 저장됩니다 — 근거 구절이 원문에 실제로
없으면 저장 자체가 거부됩니다.

이건 우회가 아니라 계약이 지시한 구조입니다. 계약의 다섯 번째 원칙이 "애매하면 판단하지
않고 사람에게 넘긴다"이고, R-12는 확신도 low를 무조건 `unknown` + 담당자 질문으로
보내라고 명시합니다. 코드는 확신 가능한 구간만 처리하고 나머지는 검수 관문으로 올립니다.

바뀐 것은 **큐를 가져가는 주체**뿐입니다. 외부 자동화(n8n 등)를 쓰고 싶으면
`GET /handoff/pending` → `POST /handoff/{id}/callback` 경로가 그대로 열려 있습니다.

### R-05를 code에서 code+ai로 옮긴 이유

원래는 서식을 곧 의미로 옮겼습니다 — 빨강은 고칠 표현, 굵게+밑줄은 권장 표현.
그런데 **강사가 좋은 점이든 나쁜 점이든 가리지 않고 전부 굵게 칠하는 경우**가 있습니다.
그러면 권장 표현과 고칠 표현이 통째로 뒤바뀝니다.

지금은 **서식이 "어디를 보라"까지만 말하고, "무엇인지"는 문장을 읽어 판정**합니다.
서식이 아예 없어도 `"A" → "B"` 같은 교정 쌍은 잡아냅니다. 서식과 다르게 판정된
구간은 `emphasis_reinterpreted`(notice) 플래그로 담당자에게 올라가고, 카드에
`key_concept → issue_expression` 같은 변경 내역이 남아 대조할 수 있습니다.

**원문 글자는 하나도 바뀌지 않습니다.** 어디에 어떤 뜻이 붙는지만 달라집니다.

## 6. 검수 관문 (severity 4단계)

| severity | 게이트 동작 |
|---|---|
| `notice` | 통과. 사유만 기록 |
| `review` | 통과하되 담당자 확인 권장 |
| `hold` | **진행 차단.** 승인 또는 제외해야 다음 단계 |
| `block_direct_quote` | 발송은 가능하되 **원문 인용 경로 차단**, 요약본만 |

`is_sendable()` 하나가 이 판정을 담당하고, 리포트 생성·발송 매핑표 양쪽에서 같은
함수를 부릅니다. 자동 모드는 이 잠금을 없앤 것이 아니라 **여는 주체를 사람에서 설정값으로
바꾼 것**이며, 누가 열었는지가 플래그에 그대로 남습니다.

```json
{ "code": "non_regular_participant", "severity": "hold", "resolved": true,
  "decision": "approve", "resolved_by": "자동 모드",
  "memo": "자동 모드에서 통과시켰습니다. 운영 모드에서는 담당자 승인이 필요합니다." }
```

## 7. 리포트 구성

### 표현 계층 (`render/adapter.py`)

백엔드의 카드는 **데이터**고 리포트 템플릿의 카드는 **표현**이라 모양이 다릅니다.
어댑터가 그 간극을 메우며, 세 가지 원칙을 지킵니다.

1. 점수 데이터는 그대로 옮긴다.
2. "가장 잘한 것 / 키울 것" 같은 판단은 여기서 만든다 — 근거는 **점수 비교뿐**이고
   문장을 지어내지 않는다.
3. 문장이 필요한 자리는 **R-16을 통과한 생성물만** 쓴다. 없으면 그 섹션을 만들지
   않는다 — 렌더러가 빈 섹션을 지우고 번호를 다시 매긴다.

그래서 사람마다 리포트 섹션 수가 다른 것이 정상입니다.

| | 누적교육 | 단발특강 | 360 진단 |
|---|---|---|---|
| 01 | 이번 회차, 한눈에 | 오늘 특강, 한눈에 | 진단 결과, 한눈에 |
| 02 | 지난 회차 이후 달라진 점 | 역량별 결과 | 누가 어떻게 보고 있는가 |
| 03 | 역량별 결과 | 오늘 잘하신 점 | 짚어 준 강점 |
| 04 | 이번에 통한 것 | 함께 살펴보면 좋을 점 | 바라는 변화 |
| 05 | 함께 살펴보면 좋을 점 | 다음까지 해 볼 것 | 다음까지 해 볼 것 |
| 06 | 나의 표현 교정 노트 | | |
| 07 | 다음까지 외울 문장 | | |

### 머리말 — 누구 것인지 종이 위에서 가릴 수 있게

```
개인 피드백 리포트
강지우 대리님
글로벌영업1팀 · 대리 · E2101
리더십 교육 2차수
```

같은 이름이 둘일 때 종이 위에서 가릴 수 있는 값은 **사번뿐**입니다. 소속·직급이
없는 사람은 그 칸만 빠지고, 가운뎃점도 앞에 무엇이 있을 때만 그립니다.

### 총점은 항목을 더해서 냅니다

어딘가에 100 을 적어 두고 그것으로 재면, 항목이 셋이든 열이든 늘 100점 만점이
됩니다. 실제로 그래서 전원이 100점으로 보였습니다.

```
3항목 × 100점  →  총점 265/300 (88.3%)
4항목 × 5점    →  총점  17/20  (85%)
```

척도도 값에서 읽습니다. 실제 값이 들어가는 가장 작은 척도(5·7·10·20·100)를
고르고, 0 이 있으면 0부터 시작하는 척도로 봅니다. 100 도 넘으면 값을 그대로
살립니다 — 임의로 100 에 맞추면 120점짜리가 100점으로 잘립니다.

### 평균 하나로 뭉뚱그리지 않습니다

평균만 크게 띄우면 `3.7 → 3.7, 변화 없음` 으로 읽힙니다. 실제로는 한 역량이 0.5
올랐고 두 역량이 새로 추가됐는데도 그렇습니다. **이전 회차가 있고 실제로 오른 역량이
있으면 그 변화를 크게 띄우고 평균은 아래로 내립니다.**

```
[ 가장 크게 오른 역량 ]
  +0.5
  Tone 3.5 → 4.0
  이번 회차 평균 4.2 (지난 회차 4.0)
  역량 구성이 달라 평균 비교는 참고용입니다
```

### 레이더 차트 (`render/radar.py`)

- 축 순서 = **원본 엑셀의 헤더 순서**
- 이번 회차 실선 + 채움 / 지난 회차 점선 회색
- 공통 축에 `▲ +0.5` 배지. **변화가 없으면 배지를 띄우지 않습니다**
- 결측 축은 `미평가` 라벨을 달고 **선을 잇지 않습니다** — 0으로 찍으면 낮은 점수로 읽힙니다
- 축이 3개 미만이면 만들지 않습니다

자바스크립트 차트 라이브러리를 쓰지 않고 **인라인 SVG**로 그립니다. 브라우저 인쇄나
headless Chrome으로 PDF를 뽑을 때 스크립트로 그린 그림은 비어 나오기 때문입니다.

### 암기 문장 카드

강사가 제시한 교정 표현을 **한 문장으로 엮어** 제시합니다. 문장 안의 각 조각이
어느 교정 표현에서 왔는지 색으로 잇고, 지난 회차 문장이 이번 강점에 등장하면
`✓ 지난 회차 암기 문장 반영 확인됨` 배지가 붙습니다(문자열 대조라 코드로 완결).

칩 색은 리포트 범례를 그대로 따릅니다 — **초록=권장, 빨강=고칠, 노랑=핵심**.
색만으로 구분하지 않도록 `✓ 권장 표현` 처럼 글자도 함께 넣습니다.

### 영어를 어디까지 옮기나

교정 노트에 영어가 섞입니다. **전부 번역하면 수업이 사라지고, 그대로 두면
무엇을 외우라는 것인지 모릅니다.** 그래서 둘로 갑니다.

| | 예 | 처리 |
|---|---|---|
| **통째로 영어** — 말하라고 가르친 문장 | `"cost reduction"` | 원문 유지 + **뜻을 아래에** |
| **한국어에 섞인 줄임말** | `one-pager로 수치 정리` | 원문 유지 + **풀이를 옆에** |

```
✕ 이렇게 말고            ✓ 이렇게
"cost down"              "cost reduction"
뜻 원가 절감 (콩글리시)    뜻 원가 절감 — 영어권에서 쓰는 표현
```

- 통째로 영어인 것의 뜻은 **R-13 번역과 같은 호출에 얹어** 받습니다 — API 를
  한 번 더 부르지 않습니다. 준 목록에 없는 것이 섞여 오면 버립니다(지어낸 것).
- 줄임말 풀이는 `glossary.py` 목록에서 찾습니다 — API 를 안 씁니다.
  `one-pager`·`softener`·`BATNA`·`hedging` 같은 **도구·분류를 가리키는 용어만**
  담아서, 말할 문장에는 풀이가 안 붙습니다.

### 개선점 AI 코멘트

`함께 살펴보면 좋을 점` 은 **강사 원문이 본문**이고, 그 아래 일정한 말투로 정리한
코멘트가 붙습니다. 강사 메모체(`~할 것`, `톤이 급해졌다`)와 동료 요청형
(`~말아주세요`)을 전부 `~합니다` 로 통일합니다.

디자인은 확정 시안과 동일합니다. 색을 바꾸려면 `render/template.py` 의 `CSS` 안
`:root` 변수만 고치면 전체에 반영됩니다.

## 8. 화면 — 프로토타입에 엔진을 붙이는 법 (`web/patch.js`)

UI 팀 프로토타입은 백엔드가 없어 호출 자리를 전부 `setTimeout` 으로 흉내 내고
있었습니다. 그 자리를 실제 호출로 바꿨습니다.

**마크업은 건드리지 않습니다.** 로직만 덧씌우고(`renderVals()` 가 돌려주는
props 위에 덮어쓰기), `tools/build_web.py` 가 그 패치를 번들 안에 끼워 넣습니다.
UI 팀이 새 판을 주면 빌드 한 번으로 다시 붙습니다.

```bash
py -3.10 tools/build_web.py "…/교육 평가 리포트 웹페이지_0806V5.html"
```

빌드가 하는 일 셋 — 한글 폰트 TTF 를 빼고(16MB → 600KB) CDN 링크로 되살리기,
패치 붙이기, **패치가 실행되는 자리에 들어갔는지 검증하기.** 마지막 것은
한 번 당해서 넣었습니다: 패치가 JSON 문자열 바깥에 떨어졌는데 파일은 멀쩡히
만들어지고 페이지도 열렸습니다. 아무 일도 안 일어날 뿐이었습니다.

### 예시 자료를 지웁니다

프로토타입에는 그럴듯한 숫자가 박혀 있습니다. 아무것도 안 올렸는데 검수 명단에
여섯 명이 있고, 인사이트에 `최근 회차 평균 87.0 · 이수율 96%` 가 뜨고, 자동
인사이트가 `갈등 조정 항목이 과정 평균보다 6점 높다` 고 말합니다. 진짜로
읽히고, 담당자가 그걸 보고 판단하면 사고가 됩니다.

**칸은 남기고 값만 지웁니다** — 칸까지 없애면 무엇이 들어올 자리인지 모릅니다.
다만 `1차·2차·3차` 처럼 **몇 번 있었느냐가 곧 자료**인 눈금은 통째로 비웁니다.

### 화면에서 고친 것들

| | |
|---|---|
| 위 띠 | 뒤로·이름표·리포트 목록·로그아웃을 한 줄로 모으고 **본문을 그만큼 내림** — 띄워 두면 무엇과든 겹칩니다 |
| 회차 전환 | 누적 과정은 회차마다 리포트가 따로 있습니다. 지난 회차도 보고 보낼 수 있습니다 |
| 키워드 줄 | 사이드바 목차가 좁은 화면에서 접혀서, 본문 위에도 같은 키워드를 둡니다 |
| 보류 사유 | '보류' 라고만 하면 판단할 근거가 없습니다. 사유와 **할 일**을 같이 적습니다 |
| 잘리던 문구 | 문구를 줄이지 않고 칸을 늘립니다. 바깥이 자르면 바깥까지 풉니다 |

> 화면 요소를 DOM 으로 손댈 때는 **스타일 문자열에 기대지 않습니다.** 브라우저가
> `margin-bottom:20px` 을 `margin-bottom: 20px` 로 정규화하고, `var(--radius-circle)`
> 은 값으로 치환됩니다 — 둘 다 실제로 물려서 아무 일도 안 일어났습니다. 지금은
> 글자·그려진 크기로 찾고, 못 찾으면 몇 번 더 봅니다(늦게 그려지는 컴포넌트).

## 9. HRD 대시보드 (`/dashboard`)

개인 리포트가 "나는 어떤가"를 답한다면, 대시보드는 "우리 과정은 어떤가"를 답합니다.

| 블록 | 내용 |
|---|---|
| 조직 성장 지표 | 차수별 평균과 증감. 청강생·제외 대상은 집계에서 빠집니다 |
| 강사별 성장폭 | 첫 회차 대비 마지막 회차 변화 — 강사 간 비교 |
| 영역별 히트맵 | 어느 역량이 더디게 개선되는가 → 다음 특강 주제의 근거 |
| 데이터 신뢰도 알림 | 원본 평균과 엔진 재계산이 어긋난 건 (R-03) |
| 비정규 참가자 | 발송 보류 대상 일괄 확인·승인 (R-07·R-15) |

**차트 설계** — 모든 차트가 **단일 계열**입니다. 색으로 항목을 구분하는 지점이 없어
색각 이상에서도 읽는 데 지장이 없고 범례가 필요 없습니다. 히트맵은 한 색의 명도
5단계(순차)만 쓰고 무지개 배색을 쓰지 않습니다. 값은 전부 숫자로도 적혀 있어 색이
유일한 전달 수단이 아닙니다. 셀 안 숫자 대비는 최소 4.63, 상태 잉크는 최소 5.24로
계산해 확인했습니다(기준 4.5).

## 10. 처음 보는 양식

`detect.py` 는 컬럼 위치를 하드코딩하지 않습니다. 아래는 전부 **실제 파일에서 터진 뒤**
넣은 것들입니다.

- 헤더 행: 문자열이 가장 촘촘하고 아래에 데이터가 있는 행
- **값의 성질을 라벨보다 먼저 봅니다.** 숫자 비율 80% 이상이면 점수 열이고, 라벨 힌트는
  그다음입니다. (역량명 `이해관계 파악` 이 "관계" 때문에 관계 열로 오인돼 통째로
  사라지던 문제)
- **머리글이 두 줄이면 첫 줄만 역량명**, 둘째 줄은 정의문입니다. 둘째 줄이 회차마다
  `문법·어휘 정확성` → `Grammar & Vocabulary` 로 바뀌면 같은 역량이 다른 역량이 되어
  성장 비교가 통째로 어긋납니다
- **이름 칸의 `서준혁 (Aiden)`** 은 이름과 별칭으로 나눕니다
- 평균·합계 열은 역량이 아니라 **원본 평균**으로 따로 빼서 R-03 비교에만 씁니다
- 서술 열: 평균 글자 수 기준 / 이름 열: 라벨 힌트 → 실패 시 짧은 문자열 열을 medium
  확신도로 잡고 **추측했다는 사실을 경고로 올립니다**
- 방향: 관계 열 + 이름 반복 → `aggregated_responses`
- 문항정의 시트: 시트 이름이 아니라 `Q1·Q2…` 로 시작하는 열이 있는지로 찾습니다
- 역량 대조는 이름 하나가 아니라 **가질 수 있는 이름 전부**(원본명·표준명·문항번호)로
  합니다. 표준 역량명은 승인 시점에 따라 업로드마다 달라지기 때문입니다
- 차수 라벨은 `2차수 · A조` → `2차수` 로 표준화합니다. 파일마다 조 표기가 붙었다
  말았다 하면 한 회차가 두 칸으로 갈라집니다

판별 실패는 예외를 던지지 않고 `unknown` + `warnings` 로 남겨 담당자에게 올립니다.

## 11. 저장 전략

카드는 중첩이 깊고 `context` 의 키가 원본 라벨 그대로라 과정마다 다릅니다.
전부 관계형으로 펼치면 새 양식이 올 때마다 스키마가 깨지므로, `card_json` 을 진실의
원본으로 두고 조회·필터에 쓰는 값만 컬럼으로 뽑았습니다. 계약 원칙 "원본은 고치지
않는다"의 저장 계층 버전입니다.

저장 직전 `json_safe()` 가 한 번 훑습니다. 엑셀에는 파이썬 객체로 읽히는 값이
여럿 있고(서식이 섞인 셀, 날짜, 수식 결과), 그대로 두면 저장 시점에 터집니다.
모르는 타입은 버리지 않고 문자열로 남깁니다 — 값이 사라지는 것보다 모양이 바뀌는
편이 낫습니다.

## 13. 신원 — 이 리포트는 누구 것인가

평가지에는 **이름만** 적혀 있습니다. 사번·직급·이메일은 **사원 명부**
(`seed/employees.csv`, 41명)에서 옵니다. 서버가 뜰 때 자동으로 올라갑니다.

### 사번을 제일 먼저 봅니다

이름은 겹치지만 사번은 안 겹칩니다. 사번이 있으면 동명이인 문제 자체가
생기지 않습니다.

| 평가지 이름 칸 | 결과 |
|---|---|
| `최건우 E3205` · `최건우 (E3205)` | 바로 확정. 직급·메일까지 따라옴 |
| `최건우 E2101` (오타) | **사번≠이름** 보류 — 리포트는 만들고 발송만 막음 |
| `최건우` (사번 없음) | 아래 4단계로 |

> 평가지에 사번을 같이 적어 주면 확인 절차가 통째로 없어집니다. `사번` 열을
> 따로 만들어도 됩니다.

### 동명이인 — 엔진은 절대 고르지 않습니다

잘못 고르면 남의 평가서가 엉뚱한 사람에게 가고, 아무도 모릅니다.

1. **사번** 이 있으면 끝
2. **별칭** 으로 좁힙니다 — `한지원 (Grace)` → E2106
3. **조·차수·부서** 로 좁힙니다
4. 그래도 둘 이상이면 → **보류.** 검수 화면에 후보가 단추로 뜨고, 담당자가
   고르면 사번·이메일·직급·소속이 한꺼번에 붙습니다. 사번을 직접 칠 수도
   있고, 이름이 다르면 되묻습니다. **그 판단을 기억해 다음 회차엔 안 묻습니다.**

### 명부에 없는 사람

임시 사번(`P0001`)으로 자동 등록하고 `seed/employees.csv` 와
`seed/employees.xlsx` 양쪽에 적습니다. **하지 않는 것 둘이 요점입니다.**

- **이름이 이미 명부에 있으면 안 넣습니다** — 없던 동명이인을 우리가 만들어
  내는 셈이고, 그때부터 어느 쪽이 진짜인지 아무도 모릅니다.
- **메일 주소는 지어내지 않습니다** — 그래서 리포트는 나오지만 **발송은 계속
  막힙니다.** 이것이 여는 것은 '명부에 없음' 하나뿐입니다.

`/roster/setup` 에서 임시 사번 목록을 보고 구성원으로 들어가 확인할 수 있습니다.
`HR_ROSTER_AUTOADD=0` 으로 끕니다.

### 로그인

| | 누가 | 어떻게 |
|---|---|---|
| 담당자 | 비고가 `HRD` 로 시작하는 사람만 | 사번. 인사팀이어도 교육 **받으러 온** 사람은 못 들어옵니다 |
| 구성원 | 명부에 있는 누구나 | 사번. 자기 리포트만 보입니다 |

`seed/employees.xlsx` 에서 담당자는 **노란 줄**, 자동 등록은 **붉은 글씨** 입니다
(색 뜻은 「읽는 법」 시트에). 사번으로 못 박으려면 `HR_STAFF_IDS`.

비밀번호는 아직 안 봅니다 — 회사 계정 체계가 붙기 전까지의 임시 관문이고,
'담당자만' 이라는 최소한의 선부터 그은 것입니다.
