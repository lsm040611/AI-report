# 화면 고치기

이 폴더에 두 개가 있습니다.

| 파일 | 무엇 | 누가 |
|---|---|---|
| `patch.js` | 화면 ↔ 엔진 연결 코드. **여기를 고칩니다** | 우리 |
| `index.html` | 빌드 결과물. 손대지 마세요 (다음 빌드 때 덮어써집니다) | 자동 생성 |

원본 프로토타입(디자인 툴이 뽑은 10MB HTML)은 이 저장소에 없습니다.
UI 트랙이 카톡으로 보내 주는 그 파일입니다.

---

## 고치고 확인하기

```bash
# 1. patch.js 를 고친다
# 2. 다시 빌드한다
py -3.10 tools/build_web.py

# 3. 서버가 켜져 있으면 브라우저 새로고침만 하면 됩니다
```

서버는 요청이 올 때마다 `index.html` 을 읽습니다. **빌드 → 새로고침이면 끝**입니다.
서버를 다시 켤 필요 없습니다.

인터넷(Render)에 반영하려면 그 뒤에:

```bash
git add -A
git commit -m "무엇을 고쳤는지"
git push
```

푸시하면 Render 가 알아서 3~5분 안에 다시 올립니다.

---

## 마크업(화면 모양)을 바꾸고 싶을 때

`patch.js` 는 **로직만** 바꿉니다. 버튼 위치나 글자 같은 모양은 프로토타입
원본에 들어 있고, 그 파일은 UI 트랙 소유입니다.

- **모양을 바꾸려면** → UI 트랙에 요청해서 새로 뽑은 파일을 받고,
  `py -3.10 tools/build_web.py "새파일.html"` 로 다시 빌드
- **급하면** → `patch.js` 에서 DOM 을 직접 만져도 됩니다. 뒤로가기 버튼이
  그렇게 붙어 있습니다 (`_paintBackButton`). 원본이 새로 와도 살아남는다는
  장점이 있고, 대신 저쪽 디자인과 어긋날 수 있습니다.

원본 마크업을 직접 고치지는 마세요. UI 트랙이 다시 뽑는 순간 사라집니다.

## 빌드가 하는 일

1. 한글 TTF 폰트 7개(16MB)를 들어냅니다 — 같은 서체의 woff2 가 이미 있어
   화면은 그대로입니다. **10MB → 530KB**
2. `patch.js` 를 로직 스크립트 **안쪽 끝**에 붙입니다
3. 제대로 들어갔는지 검사합니다

3번이 중요합니다. 예전에 패치가 실행되지 않는 자리에 들어간 적이 있는데,
파일은 멀쩡히 만들어지고 페이지도 열렸습니다 — 아무 일도 안 일어날 뿐이었죠.
지금은 그런 경우 빌드가 멈춥니다.

```
검증 — 패치가 로직 스크립트 안에서 실행됩니다
```

이 줄이 안 나오면 뭔가 잘못된 겁니다.

## `patch.js` 안에서 무엇이 어디에 붙어 있나

| 프로토타입이 부르던 것 | 실제 호출 |
|---|---|
| `simulateUpload` | `POST /uploads/analyze` |
| `generateReport` | `POST /uploads/{draftId}/commit` |
| `startSend` | `POST /reports/send/upload/{uploadId}` |
| `testSend` | `GET /reports/mail/status` |
| 리포트 본문 자리 | `GET /reports/{id}/body?scope=.hr-body` |
| 문장 클릭 | `GET /reports/{id}/evidence` |
| 인사이트 탭 | `GET /insights/courses` · `/insights/course/{id}` |

값을 갈아끼우는 자리는 `Component.prototype.renderVals` 를 감싼 함수입니다.
`render` 가 아니라 **`renderVals`** 입니다 — 이 프로토타입의 값 생성기 이름이
그렇습니다. 잘못 짚으면 오류도 없이 예전 더미가 계속 보입니다.
